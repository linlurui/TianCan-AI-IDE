# 微任务队列：单轮任务内也用最小提示词完成

目标：把「一个大需求 → 一整段越来越长的对话」改成
「规划一次 → 拆成微任务入队 → 每个任务只喂它需要的那点上下文 → 完成即归档」。
这样提示词规模从 O(会话历史) 变成 O(单个任务) + 常量，单轮内也一样。

配套的锚点设计见 docs/anchor-design.md（每个任务 = 一个 turn 锚点，完成即归档）。

---

## 1. 为什么不直接"少喂点历史"就够了

历史正文里真正对当前这一步有用的只有三样：约束（红线/约定）、契约（会用到哪些签名）、
当前这一步要改的文件片段。其余 90% 是已经完成的工作的正文和工具流水。
压缩（compact）是"事后删"，而队列是"事前不产生"——后者更省，也更不容易删错东西。

代价是：切开之后模型看不到前序代码，跨文件一致性会变差。
所以必须先做下面那步 —— **契约先行**。

## 2. 契约先行（T0）

规划阶段除任务清单外，必须额外产出一份 **契约**，作为任务 T0 先落盘：

```
契约 = 新增/修改的类型、接口、函数签名、数据结构、路由、事件名
     + 每个任务的落点文件清单
     + 命名与风格约束
```

契约是队列的"共享内存"：后面每个任务的提示词只带契约（几百 token，版本化），
不带前序任务写出来的代码正文。契约不变更就不重新注入，变更则 contract_ver++。

## 3. 规划阶段（一次性，本身就是低上下文）

输入：

- 用户需求原文
- 项目骨架：文件树 + 关键符号签名（由索引/recall 生成，只要签名不要正文）
- 活跃红线、活跃需求条目
- 已完成任务的单行摘要（**不是正文**）

输出（要求模型用严格格式输出，便于 split）：

```
T1 | 标题 | 落点文件 | 依赖:T0 | 验收:... | 需读文件:a.go,b.go
T2 | 标题 | 落点文件 | 依赖:T1 | 验收:... | 需读文件:c.go
...
```

拆分粒度标准（自动判定，模型自己也要遵守）：

- 一个任务 = 1 个文件内的一次改动，或 1 个函数，或 1 个测试
- 改动文件数 > 2 → 继续拆
- 预估改动 > 80 行 → 继续拆
- 拆到「单文件 + 单一可验收条件」为止

## 4. 队列持久化（memdb 新表 tasks）

内存队列崩了就没了，必须落库，才能跨重启续跑、能回退、能在 UI 上看见。

```sql
CREATE TABLE IF NOT EXISTS tasks(
  hash TEXT NOT NULL,        -- 项目
  id   TEXT NOT NULL,        -- 会话
  tid  INTEGER NOT NULL,     -- 任务号
  parent   INTEGER DEFAULT 0,
  title    TEXT,
  body     TEXT,             -- 任务描述
  files    TEXT,             -- JSON: 落点文件
  deps     TEXT,             -- JSON: 前置任务号
  reads    TEXT,             -- JSON: 需读文件
  accept   TEXT,             -- 验收条件（会被真实命令验证）
  status   TEXT,             -- pending/running/done/failed/obsolete
  contract_ver INTEGER DEFAULT 0,
  seq_after   INTEGER DEFAULT 0,  -- 完成时的会话 seq（= 归档锚点位置）
  summary  TEXT,             -- 完成后的一行摘要
  retries  INTEGER DEFAULT 0,
  PRIMARY KEY(hash, id, tid)
);
```

依赖成环则拒绝入队；同文件的相邻任务可选合并（减少往返）。

## 5. 单任务提示词装配（核心）

每个任务执行时装配的包：

```
[常量 K]  系统提示 + 红线 + 项目约定            —— 固定
[契约]    T0 的签名清单（contract_ver 版本化）   —— 固定几百 token
[当前任务] 标题 / 落点 / 验收 / 需读文件片段      —— 由 recall 检索出的片段，不是整文件
[已完成]  前面每个任务的一行摘要（≤1 行/个）
[引用]    只有用户 @引用 或命中检索时，才取回那一小段（SessionSearchAnchors）
```

明确不喂：历史对话正文、已完成任务的 diff、工具流水、未归档任务的无关消息。

规模：

```
C = K + |契约| + |单任务| + n × 1行摘要
```

n 增长只带来线性且极小的增量（每个任务一行），且归档后连这行都只剩摘要本身。
对比原来的 O(会话历史全文)，单轮内也压得住。

## 6. 完成即归档

1. 任务执行完 → 跑真实验收（build / 指定测试 / 静态检查），不自述通过。
2. 通过 → `ArchiveAnchor(seq, archived=true)`：该任务这轮的消息正文从此不再进入提示词，
   只保留锚点上的一行摘要。
3. 记录 `seq_after`，任务状态置 done，取下一个 pending 任务。

锚点地基（kind=turn / status=archived / summary）已经具备，这里只是接上。

## 7. 失败与重规划

- 失败重试：只带「任务 + 契约 + 报错 + 相关文件片段」重跑，**不带历史**。
- 连续 2 次失败 → 回滚到本任务前的快照（ralph），任务退回 pending，
  把契约与剩余任务一起交给规划器 **重规划剩余队列**（不是全量重规划）。
  重规划输入 = 契约 + 完成摘要 + 剩余任务，很便宜。
- 若某任务改了契约之外的东西 → 判为越界，拒绝并要求重规划（防止一致性崩掉）。

## 8. 顺带收益

- 每个任务都是小 diff → 审计面板（阶段二）才真的能一眼看完、敢点"同意"。
- 不冲突的任务（不同文件）可并行：parallel.Executor 已有。
- 崩溃恢复：队列在 memdb 里，重启接着跑。
- 每个任务的改动范围已知 → 提示词里的文件片段可以精确取，不必整文件。

## 9. 要防的坑

| 坑 | 防法 |
|---|---|
| 拆太碎导致跨文件不一致 | 契约先行 + 越界拒绝 |
| 单任务视角丢掉全局约束 | 红线与约定每个任务都重新注入（常驻 K） |
| 模型自述完成但其实没过 | 验收必须是真实命令 |
| 队列越攒越多 | 完成即归档 + 契约版本化，旧的失效任务标 obsolete |

## 10. 分期落地

- **P1**：memdb `tasks` 表 + 队列存取（入队 / 取下一个 / 状态流转 / 依赖校验）；
  规划提示词与结果解析器（产出 T0 契约 + 任务清单）。
- **P2**：单任务提示词装配器（接 ctxsvc 的 packer：注入契约、排除归档锚点全文、按 reads 取片段）；
  每任务跑完 → 真实验收 → 归档锚点。
- **P3**：失败重跑 / 回滚到任务前快照 / 重规划剩余队列；队列 UI（与侧边刻度尺联动：
  一个刻度 = 一个任务，颜色区分 done / running / pending / failed）。

现有可复用的部件：`types.ParallelTask` + `parallel.Executor`（队列执行器）、
`conversation` 的 requirements / redlines / anchors / recall、`ralph` 快照回滚、`compact` 压缩。
缺的是：规划器（提示词 + 解析）、tasks 持久化、契约、单任务装配器。
